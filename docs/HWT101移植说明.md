# HWT101航向传感器移植（2026-11-13）

“转盘调试”保留 `Hardware/hwt101_imu.c/.h` 和轮趣 `Hardware/lunqu_imu.c/.h`，由 `User/main.c` 的 `IMU_Select` 单变量选择，当前选择轮趣。具体值、轮趣接线及就绪条件见 [陀螺仪选择](陀螺仪选择.md)。BNO085不参与本次选择。移植前文件保存在 `D:/物流小车/代码/STM32F103C8T6_TTL/HWT101参考资料/移植前备份-20261113-215018`。以下配置及HWT显示说明适用于选择HWT101的情况。

## 接线与模块设置

| HWT101 TTL引脚 | STM32F427 A板 | 说明 |
|---|---|---|
| TX | PG9 / USART6_RX，AF8 | 沿用原航向接收引脚 |
| GND | GND | 共地 |
| VCC | 稳定3.3V电源 | 商家允许3.3～5V供电，TTL信号为3.3V |
| RX | PG14 / USART6_TX，AF8 | 必须新增此线，用于启动配置及回读 |

商家规格书“模组参数”明确写明出厂默认 **115200、10Hz**，即约每100ms更新一组数据。STM32固定 **115200、8数据位、1停止位、无校验、无流控**，按出厂设置接线即可，不需要先用电脑配置频率。旧串口协议文档对默认波特率写9600，与规格书不一致；本实现按用户要求及当前规格书使用115200，不自动扫描或修改波特率。

为了保持原车闭环反馈速度，STM32在RTOS启动后自动将模块从10Hz设置为100Hz。配置由现有MotorTask每轮调用 `IMU_Poll(now_ms)`，仅HWT101模式分流到 `HWT101_Poll(now_ms)` 推进，等待使用RTOS毫秒时间差，发送使用USART6 TXE/TC中断；不新增任务，不调用Delay或阻塞等待，不暂停编码器读取。设置只涉及输出速率和保存，不改出厂标定、零偏模式、硬件Yaw零点或波特率。

自动配置顺序：收到有效角度帧后先发 `FF AA 27 03 00`，读取RRATE及BAUD。已是100Hz/115200时跳过写入；否则发 `FF AA 69 88 B5` 解锁，确认发完后至少200ms再发 `FF AA 03 09 00`，发完至少200ms再读回RRATE，确认0x09/0x06后发 `FF AA 00 00 00` 保存。已正确设置的模块下次上电不重复写保存，正常运行也不周期查询。

随后观察至少300ms的真实角度帧，频率达到至少80Hz才确认100Hz配置就绪，避免把寄存器正确但仍只收到10Hz当成功。观察最长1秒；配置传输最长250ms、回读最长500ms，最多尝试3次；始终没有角度帧则首次轮询后3秒失败。所有计时支持毫秒回绕。

LCD航向行显示 `HWT:SET`（配置中）、`HWT:100Hz`（回读及帧率通过）、`HWT:ERR`（失败）。确认前05/07/08/12/13/14/1E的航向闭环、路线和独立原料区启动指令不执行、不回显、不排队，显示100Hz后重新发送；路线上传、06中止及纯机械调试照常。看到ERR应检查两根交叉串口线、供电及115200设置，排除后重新上电。启动配置不会自动启动车辆。

## 转弯按新帧确认到位（2026-11-14）

转弯仍要求进入±2°容差，到位确认改为连续3个新的有效角度帧（100Hz时约30ms），同一旧帧不能重复计数，偏出容差重新计数。`IMU_GetSample()` 原子读取角度和对应帧序号，HWT101模式仅校验通过的0x53角度帧增加序号；轮趣模式使用原FDILink规则接受的AHRS航向帧，软件记零及其他类型帧不增加序号。

按用户要求取消100ms断流检测及停车，不增加运行期IMU掉线故障或启动在线检查。保留上电100Hz配置验证、原有转速/PID/限斜率及普通转弯15秒总超时（相对大角度转弯60秒）。若转弯时一直没有新角度帧，到位确认不会增加，最终仍适用原有转弯总超时。编码器持续读取，机械流程不新增等待。

## 安装与航向方向

HWT101只适合水平安装。默认按 **Z轴向上** 配置，`hwt101_imu.h` 的 `HWT101_YAW_SIGN=-1.0f` 将维特Z轴右手角度转换为现有路线的“俯视车体顺时针增加”：0°→90°→180°→270°→0°。传感器在水平面内换个朝向不会影响软件记零，但翻面会改变符号。

实车安装方向尚未验证。先保持底盘电机不启动，上电等航向数据到达，按PB2归零；手动将整车顺时针转90°，LCD应约显示90°，反向回原处应约显示0°。如果顺时针90°显示270°，将该宏改为 `+1.0f` 后重新编译。方向只在此处转换，保持原有 `YAW_OUT_SIGN`、`TURN_OUT_SIGN` 和摄像头视觉Yaw方向不变，避免重复反向。

## 协议与原流程衔接

接收参考本地SDK的 `WitSerialDataIn(WIT_PROTOCOL_NORMAL)` 和商家HWT101协议，未搬入F103外设初始化、自动扫波特率、主循环或SDK阻塞延时。

| 项目 | 实现 |
|---|---|
| 帧格式 | `55 TYPE DATA[8] SUM`，固定11字节 |
| 校验和 | 前10字节累加的低8位，校验成功才使用 |
| 航向 | `TYPE=53`，第6、7字节按小端有符号int16还原，乘 `180/32768` 后映射方向；按从0开始编号 |
| 其他字段 | `53`帧第8、9字节为版本号；`52`为角速度帧，均不冒充新航向 |
| 坏帧处理 | 滑窗重新找55帧头；ORE/FE/NE/PE时SR→DR清错并丢弃受影响帧，后续有效帧自动恢复 |
| 中断 | USART6优先级4，RXNE有界解析、TXE发送5字节命令、TC确认发完；不调用RTOS API、Delay或SysTick |
| 控制与显示 | `IMU_GetYaw()`输出(-180,180]，`IMU_GetYawAbs360()`输出[0,360) |
| 更新序号 | 仅有效53角度帧递增，角速度/噪声/坏帧不能满足原料区启动检查 |

原有归零、重设均保留为STM32软件偏移，不等待传感器硬件归零；后续数据持续使用此偏移。上电首个有效角度帧将当前朝向记0°；PB2及连续两批 `13/03`记0°；原料区独立 `1E`将启动朝向记90°；真实路线两轮粗加工、两轮暂存完成视觉XY/Yaw后，分别记270°、0°并重置直行航向控制历史。独立视觉、`1C`纯机械调试不新增航向重设。

转弯速度/PID、机械动作参数、RDK协议及编码器连续读取保持原参数。电机任务将原来轮趣专用的设角调用换成统一 `IMU_SetYaw()`，由imu.c统一分流HWT101或轮趣；HWT101增加启动自动配置轮询和就绪检查，轮趣只等首个AHRS帧；LCD航向行显示所选源及就绪状态。OdomTask和按键使用统一imu.h航向接口。

软件重设只改变参考方向，不会消除传感器自身的角速度零偏。若静止时持续漂移，按商家流程在完全静止条件下用上位机获取零偏；不能在行驶中随意执行零偏获取。本次未自动增加20秒零偏校准或机器人静止/运动通知，避免改变现有动作节奏。

## 验证结果与限制

- 使用实际新驱动和商家原SDK回放全部65536个有符号Yaw原始值，验证字节序、符号、比例、归一化和版本字段隔离。
- 验证上电/PB2/13归零、原料区90°、两轮粗加工270°/两轮暂存0°，新帧偏移持续生效、跨±180°和360°边界、首帧前记角及临界区中断屏蔽状态恢复。
- 验证每个位置丢字节/插入字节、88个单比特错误、混合帧型、100000字节噪声，以及实际ISR的四类串口错误恢复。
- 使用实际驱动及模拟模块验证出厂10Hz→100Hz、已100Hz仅回读、不重复写保存、缺少回传线/坏回读/写入不生效/错误BAUD/假100Hz/发送或TC中断卡住/无传感器时有界失败；确认并行收发不丢角度帧、200ms间隔从TC发完后开始、计时及帧序号回绕正常。
- 验证实际启动检查及LCD显示：未就绪的路线不启动，06/上传/纯机械命令保留，SET/100Hz/ERR航向行均不超过21字符。
- 验证取消100ms断流停车及相关启动在线限制；转向原有总超时保留，角度与序号快照一致，帧序号回绕正常。
- 回归现有转弯及定位限速测试，保留方向、±2°容差、360°累计、18/8RPM限速等既有参数；转向必须3个新角度帧确认，旧帧不误完成，偏出容差重新计数。
- Keil完整重编译：**0错误、0警告**。生成 `Objects/Project.hex`，未自动烧录。

以上属于协议、代码和编译验证，尚无HWT101接车后的实测数据，不能据此保证实际安装方向、动态滞后、漂移、打滑或停车精度。按上述方法确认方向和100Hz后，再验证90°/270°转向与原料区、粗加工及暂存航向重设。
