# 路线调试记录

本文记录用户提供的点对走法和实测状态。后续每确认一组点对，就追加对应规则和控制帧；STM32按上位机上传顺序调用规则，不推测未提供的直行距离。

## 到站作业航向（2026-10-09）

| 任务站点 | 作业yaw | 当前预留动作 |
|---|---:|---|
| 扫码区 | 0° | 对准后停车、蜂鸣500ms，预留扫码 |
| 原料区 | 90° | 对准后停车、蜂鸣500ms，预留夹取 |
| 粗加工区 | 270° | 对准后停车、蜂鸣500ms，预留放置 |
| 暂存区 | 0° | 对准后停车、蜂鸣500ms，预留放置 |

网页保留寻路的点序和禁行限制，在任务站点处分开行驶段。普通行驶仍用前进/后退，
不会用两次90°转向代替后退；与车头垂直的路段允许反向转90°后倒车，以便到站时
已经对准或只需一次90°调整。方案优先少改动旧动作，其次减少转弯；没有可行朝向时
显示航向冲突并禁止发送/启动。仅任务终点执行作业，同名点被路线途经时不执行。

下=0°、左=90°、上=180°、右=270°。例如中心点以yaw=90°出发：

```text
中心点 → 顺时针90° → 前进 → 原料区
→ 逆时针90°到yaw=90° → 夹取预留500ms
→ 逆时针90° → 前进 → 粗加工区
→ 逆时针90°到yaw=270° → 放置预留500ms
→ 后退 → 左下角 → 顺时针90°到yaw=0° → 后退 → 暂存区
→ 放置预留500ms
```

原料区两次90°之间留有夹取节点，不能合并为180°。暂存区对准后的yaw=0°用于
第二批的起始朝向。当前只用500ms定时停顿占位，不表示机械臂已完成真实操作；
后续接入机械臂时需在此等待实际动作完成再继续。

协议仍为每段`04`动作帧加`01/03`坐标帧。作业节点使用`01`、点数2、两个相同
站点坐标；动作码1表示已对准，3/4表示顺/逆时针90°对准。STM32校验站点和最终
yaw，执行后只停顿一次500ms，再取下一段；不符合站点航向的节点按`no next`保护
停车，不平移。转弯仍抵消里程计1自转计数。直线保持用户给定的正负行程；上传航向
与标定航向相差180°时，只反转行程正负，保持上传的yaw，不强制回到标定yaw。

现已加入中心点→原料区、右上角→原料区、原料区→粗加工区的用户给定行程；
粗加工区→左下角、左下角→暂存区、暂存区→左上角、左上角→原料区也已加入。
实际调试仍在第一个未知路段停下、蜂鸣5秒、显示`no next`。批次1、批次2均可单独
启动，也可用连续启动帧在第一批完成后自动衔接第二批；批次2必须从暂存区上传，
两批连续时第一批末点必须与第二批首点都是暂存区。

## 启停区2的初始位置（2026-10-09）

批次1路线首点的发送坐标是 `(2200,200)` 时，识别为启停区2；`(2200,2200)` 是启停区1。出发区与任务批次是两个概念，启停区2出发的第一批仍发送同一条启动帧 `AA 55 13 01 14 0D 0A`。

点击一键启动后，启停区2将当前里程计1原始编码值映射为路线 `pos=1450000`。计算规则：

```text
偏移 = 1450000 - 启动时原始pos
路线pos = 最新原始pos + 偏移
```

只增加坐标偏移，不翻转计数方向。原始计数减少100000时，路线pos从1450000变成1350000；它不是立即变成负100000。自动点对规则的绝对目标换算成原始目标 `绝对目标 - 偏移`，相对增量仍按当前原始pos累加，两者与PID反馈使用同一坐标。

LCD增加 `pos:` 行显示路线累计值，原 `p1` 行仍显示原始编码值。启停区1启动清除此偏移，沿用已有标定坐标；两区出发车头都朝下，初始目标yaw仍为0°。收到上传数据不改变位置，只有有效13启动时才建立起点映射。手动05/08帧和旧12任务数组继续使用原始编码坐标，不修改协议含义。

启停区2→右下角45度使用右后45°平移，纵向行程 `100000`；右下角45度→扫码区相对 `-520000`，均保持yaw=0°。
首次到原料区前，扫码区后面的绝对定位保持原值，以校准二维码板位置变化。

## 自动航向与顺序执行

启停区1初始目标yaw为0°。STM32维护已完成动作的目标航向，只有0°、90°、180°、270°；实际陀螺仪仍提供连续角度反馈，不对反馈四舍五入。

| 当前目标yaw | 顺时针90°后 | 逆时针90°后 |
|---:|---:|---:|
| 0° | 90° | 270° |
| 90° | 180° | 0° |
| 180° | 270° | 90° |
| 270° | 0° | 180° |

上位机04动作码3/4分别表示顺时针/逆时针90°；01/03坐标段给出这次转向后的行走点序。转向只在该坐标段开始时执行一次，同段后续点对继承转完的yaw，前进/后退不改变yaw。已提供距离的直行会自动继续，距离尚未提供时只完成已知转向，随后停车、鸣叫5秒并显示 `no next`。

扫码区→中心点仍是一个复合点对：先绝对pos=725000校准，再执行该段转向，再相对+620000。默认上位机动作码3使yaw从0°变为90°；复合规则自带的转向与上位机转向合并执行一次。转完后的yaw自动用于+620000直行；没有转向动作码时沿用用户标定的绝对90°。

以上`+620000`是顺时针转到yaw=90°的标定走法。若规划选择反向转到yaw=270°，
点序仍向左，则相对行程使用`-620000`倒车到中心点；距离不从地图推算。

已知点对规则集中在 `Task/motor_task.c` 的 `debug_rules[]`；上传缓存顺序提供每个点对和它的转向动作。未知点对停止，不在整条路线中向后搜索其他已知点对，也不自动按地图距离生成行程。

### 首轮校准与反向复用（2026-10-10）

首次到达原料区之前保留两条扫码区绝对定位，包括从启停区2出发的路线。首次原料区
行驶完成后切换为相对定位；连续两批保留此状态，单独启动第二批直接使用相对定位。
重新启动第一批重置校准状态，中止后重新上传第一批也会重新校准。

标定扫码位置为 `620000`：扫码区→右上角的原行程为 `110000-620000=-510000`，
扫码区→中心点的首段为 `725000-620000=+105000`。这两个增量固定在段启动时累加当前pos，
不使用第二批的累计位置追赶首轮绝对目标。上传航向与对应步骤原标定航向相反时，只反转
该步骤增量；扫码区→中心点仍按三个内部步骤顺序执行。其它相对点对的距离、停顿和作业预留不变。

## 单段控制帧

启停区1到右上角45度：

```text
AA 55 08 01 03 A0 86 01 00 00 00 33 0D 0A
```

- `CMD=08`：高级运动帧。
- `SUB=01`：右前45°。
- `FLAGS=03`：相对位置 + 指定目标 yaw。
- 位置增量：`100000`。
- 目标 yaw：`0°`。

右上角45度到扫码区：

```text
AA 55 08 00 03 40 EF 07 00 00 00 41 0D 0A
```

- `CMD=08`：高级运动帧。
- `SUB=00`：直线。
- `FLAGS=03`：相对位置 + 指定目标 yaw。
- 位置增量：`520000`。
- 目标 yaw：`0°`。

相对位置的计算规则是：启动该段时读取当前累计 `pos`，只计算一次 `目标 = 当前 pos + 增量`。因此第二段不是从零开始，而是在第一段结束位置上继续累加 `520000`。

## 路线上传和一键启动

路线规划上位机先发送批次1的动作帧和坐标帧。STM32 收到后只记录并回传，不直接发车。网页收到全部回传后，点击“调试一键启动（批次1）”，发送：

```text
AA 55 13 01 14 0D 0A
```

`0x13` 是已上传路线的调试启动帧：`01`启动第一批，`02`启动第二批，`03`连续启动两批。STM32收到后从上传路线的第一个点对开始，按顺序执行已配置点对和90°转向；启动资格使用一次，下一次运行前需要重新上传路线。运行期间重新上传的路线不会替换正在执行的点序。
