# 上位机路线规划计算规范(配合车端 04 动作帧)

> 面向对象:上位机(网页端)开发者。
> 车端职责:接收动作指令,**精确执行每一段**(前进/后退/转 90°),毫米级闭环。
> 上位机职责:**规划路线**——把"从哪到哪、绕什么障碍"分解成一段段"直行+转弯",算好每段距离,按顺序发下来。
> 分工一句话:**上位机算"走多远、往哪转",车端只负责"走准"。**

---

## 一、车端执行能力(上位机可用的"积木")

| 动作 | 精度 | 说明 |
|---|---|---|
| 前进 / 后退 N mm | ±2mm(闭环) | 沿当前车头方向;N 范围 1~2400 |
| 原地顺时针转 90° | ±2° | yaw 闭环,转完即停 |
| 原地逆时针转 90° | ±2° | 同上 |
| 缓行+扫码停车 | — | 特殊段:6RPM 慢速前进,扫到二维码自动停(用于去扫码点) |
| 中止 | — | 任意时刻停车回空闲 |

> 车端换算:1mm = 604.17 编码值(已标定),**上位机直接发毫米数即可**,不用管编码值。

## 二、下行帧格式

### 动作帧(直行段)
```
AA 55 | 04 | BATCH | CODE | D0 D1 D2 D3 | SUM | 0D 0A     (11字节)
```
- BATCH:1=第一批 2=第二批
- CODE:1=前进 2=后退 3=顺时针转90° 4=逆时针转90°
- D0~D3:直行距离,**毫米,int32 小端**(转弯时填 0)
- SUM = (04+BATCH+CODE+D0~D3) 累加和低 8 位

### 转弯也可用定位帧(等价方式)
```
AA 55 | 05 | 02 或 03 | 5A 00 00 00 | SUM | 0D 0A      (左转/右转90°)
```

### 一键任务数组帧
```
AA 55 12 12 0D 0A
```
车端按**内置步骤表**从当前步骤连跑到尾(步骤表见文末,数值可在车端代码改)。

### 中止帧
```
AA 55 06 06 0D 0A
```

## 三、上位机需要计算的三件事

### 1. 车头朝向跟踪(状态量,不是计算量)

维护一个变量 `heading`(车头朝向,单位度,顺时针为正):

```
初始:heading = 180      (0=朝上/北, 90=朝右/东, 180=朝下/南, 270=朝左/西)
      —— 本车出发时车头朝下,即 heading = 180
每执行"顺时针转90°":heading = (heading + 90) mod 360
每执行"逆时针转90°":heading = (heading + 270) mod 360   (即 -90)
```

### 2. 直行段距离(两点距离公式)

从当前位置 (x, y) 到目标点 (tx, ty),且**车头已对准目标方向**时:

```
直行距离 = sqrt((tx - x)² + (ty - y)²)      (mm,四舍五入取整)
```

### 3. 对准目标所需的转角(决定发"顺转"还是"逆转")

```
目标方位角 = atan2(tx - x, ty - y) × 180/π      (0=朝上, 顺时针为正, 0~360)
需转角度  = (目标方位角 - heading + 360) mod 360

若 需转角度 ≤ 180 → 发 CODE=3(顺时针)×1 次,转 需转角度?—— 本车转弯固定90°一档:
   需转角度 = 90   → 发 1 次 顺/逆(按最短方向)
   需转角度 = 180  → 发 2 次 同方向 90°(或 1 次 180°,若扩展)
   需转角度 >180   → 反方向转 (360-需转角度)
```

> 本车当前转弯指令只有 ±90° 一档;180° = 连发两次同方向。

## 五、路线分解规则(每改变一个方向 = 一步)

上位机把完整路线拆成动作序列的规则:

1. **沿当前车头方向能直达的下一段** → 一个"前进/后退"动作(带距离);
2. **需要改变方向处** → 一个"顺/逆时针转90°"动作;
3. 每个动作帧 = 一步,按顺序发送;车端每步执行完停稳,等下一帧;
4. **绕障碍** = 在障碍物处插入"转→直行→转"三段,距离按绕行路径计算;
5. 建议段长别小于 100mm(太短转弯次数多、耗时长)。

### 计算示例(第一批,启停区1 出发,车头朝下 heading=180)

出发位置:启停区1 中心 (2250, 226),车头朝下。

| 步 | 目标 | 计算 | 发送 |
|---|---|---|---|
| 1 | 前进到扫码点 (2250, 1200) | 距离 = 1200−226 = **974mm**(同 X,直行) | `04 01 01 D=974` |
| 2 | 后退回右上角 (2250, 226+165) | 距离 = 当前Y − 391 ≈ **809mm**(反向,发后退) | `04 01 02 D=809` |
| 3 | 顺时针转 90° | 车头 朝下→朝左 | `04 01 03 00000000` |
| 4 | 前进到原料区 (1200, 250) | 需先对准:此段含横移分量,建议拆两步(见下) | 见下 |

> **斜行/两段拆分**:车头朝左时到原料区需要"向左直行 + 向上修正"两个分量。
> 两种做法任选:
> a. **两段直行**:先"前进"(向左)走 1050−165≈884mm 到中线,再"逆时针转90°"(车头朝上)再"前进"走 950mm 到原料区——动作多但每段都是闭环直行,精度最高;
> b. **45° 斜走**:车端已预留 45° 斜走能力(方向码),距离 = 两点直线距离,一次到位但精度略低。
> **建议比赛用 a(两段直行),调试期用 b 快速验证。**

## 六、一键任务数组(车端内置,0x12 触发)

上位机也可以**不逐帧发动作**,车端内置了"第一批"步骤表(下表,数值实测后改车端 `Task/motor_task.c` 的 `task_z1[]`),发一条 `AA 55 12 12 0D 0A` 即自动连跑:

| 步 | 动作 | 步长(编码值) |
|---|---|---|
| 0 | Y 轴闭环到 650000(扫码区) | 650000 |
| 1 | Y 轴回 100000(右上角) | -550000(相对) |
| 2 | 顺时针转 90° | — |
| 3 | X 轴闭环到 250000(原料区) | 250000 |
| 4 | 逆时针转 90° | — |
| 5 | Y 轴闭环到 1370000(粗加工区) | 1370000 |
| 6 | 顺时针转 90° | — |
| 7 | X 轴闭环到 1330000(左下角) | 1330000 |
| 8 | 顺时针转 90° | — |
| 9 | X 轴闭环到 725000(暂存区) | 725000 |

> 数组模式下车自动连跑;单步模式(04/05 帧)与一键可混用;06 帧随时中止。
