# 陀螺仪选择（2026-11-14）

轮趣FDILink和维特HWT101驱动均保留在工程中，由 `User/main.c` 的一个变量选择：

```c
uint8_t IMU_Select = IMU_SOURCE_LUNQU;
```

| 变量值 | 启用的陀螺仪 | 波特率与接线 | 启动就绪条件及LCD |
|---|---|---|---|
| `IMU_SOURCE_HWT101`，即 `0` | 维特HWT101 | 115200；TX→PG9，RX→PG14，共地 | 上电非阻塞配置并验证100Hz；`HWT:SET`→`HWT:100Hz`，失败`HWT:ERR` |
| `IMU_SOURCE_LUNQU`，即 `1`（当前选择） | 轮趣FDILink | 沿用原921600；TX→PG9，共地，仅接收 | 等首个AHRS航向帧；`LQ :WAIT`→`LQ :READY`，不发送HWT101配置指令 |

修改变量后重新编译、烧录并上电生效。两款共用USART6和PG9，实际只接所选的一款，不能将两个模块的TX同时接PG9。HWT101的供电、水平安装及方向说明见 [HWT101移植说明](HWT101移植说明.md)；轮趣沿用原模块供电及安装方向。波特率指主控与陀螺仪之间的USART6，与网页使用的UART7 115200无关。

选择在 `IMU_Init(IMU_Select)` 时锁存。运行中修改变量不会切换串口波特率、解析器或航向源。非法值不初始化陀螺仪，显示 `IMU:ERR`，不允许启动依赖航向的任务。没有自动识别或两个传感器之间的故障切换。

两款共用 `Hardware/imu.c/.h` 的 `IMU_*` 接口；USART6只有一个中断入口，根据上电选择分流到对应驱动。HWT101的11字节协议、校验和与启动100Hz配置保留；轮趣从移植前备份恢复FDILink接收规则、921600波特率及AHRS字段位置，Heading使用帧内偏移27的小端float弧度值，保持原项目航向方向。轮趣沿用原例程的类型/长度/帧尾检查，不启用CRC；接收缓冲有边界保护，串口错误清理半帧，非法NaN/Inf航向不更新序号。

以下行为两款一致：

- 上电首帧当前朝向记0°；PB2及连续两批启动13/03重新记0°。
- 独立原料区1E启动时当前朝向记90°。
- 真实路线视觉对位成功后，两轮粗加工当前朝向记270°，两轮暂存记0°；后续新帧保持该软件偏移。
- 转弯进入±2°后，连续3个新的航向帧确认到位；重复读取同一帧不计数，偏出容差重新计数。轮趣按实际AHRS输出频率计时，不强制设100Hz。
- 不增加100ms运行期断流停车。原有普通转弯15秒、大角度转弯60秒总超时仍保留。
- 编码器全程持续读取，机械动作参数和RDK/UART7帧协议保持原设置。

已在电脑上使用实际两款驱动、统一中断/航向接口及转向分支回放，验证启动分流、只初始化一款、轮趣不发HWT配置、软件归零/站点重设、3个新帧确认及原转弯超时。HWT101原协议和自动配置回归通过。两款接车后的实际方向、动态精度及全程表现仍需实测。
