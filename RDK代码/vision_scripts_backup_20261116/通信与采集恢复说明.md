# RDK通信与采集恢复修订（2026-11-16）

本目录的`vision_scripts`已修订串口解析、相机采集和结果时效处理。三区抓取报文、区域编号/优先级、HSV参数、先见转动再停稳、模式号及115200波特率均保持。

## 修复行为

| 问题 | 当前行为 |
|---|---|
| 噪声`AA 55 10 40`压住后面的单发颜色命令 | 接收器仅接受模式命令0x10和合法载荷长度1/2，尽早验证模式/颜色，错误前缀逐字节滑动恢复；仍支持跨80ms等间隔的正常拆包，不以空闲时间丢半帧 |
| 同一次串口read内一条命令回调报错后，后面命令也丢失 | 每条命令独立捕获异常，后续合法命令继续处理；失败命令不发送追踪ACK |
| 相机读帧异常或底层read/open卡住 | 使用spawn启动独占V4L2句柄的采集子进程，监督线程保留最新帧；打开最长5秒，运行2秒无新鲜帧、采集退出或异常则清缓存并终止/重建采集；重试间隔300ms，不占用串口/模式锁 |
| V4L2句柄跨线程release/read竞争 | 只有采集子进程打开/读取/释放设备；父进程先terminate，等待500ms，必要时kill再等500ms；旧进程未退出时不启动新进程争抢同一设备 |
| OpenCV4/5霍夫直线数组格式差异 | 同时兼容`(N,1,4)`和`(N,4)`，解析前统一为`(N,4)` |
| 断流后仍把旧坐标当新结果发送 | 采集时间戳贯穿分发及检测；超过300ms、晚于当前时间或早于模式切换的结果作废。转盘停止发旧圆心；码垛发FLAGS=0空帧；圆环发空观测，物料保留原过期拒发规则 |
| 圆环写串口失败后清掉待发送结果 | 尚在300ms有效窗内的结果下一拍可重试；新结果仍覆盖旧结果，过期不继续重发 |

相机仍按MJPG→宽→高→帧率的原顺序配置，默认640×480@30。重开使用原请求值；如果重开后分辨率改变则保持离线重试，避免错误沿用去畸变映射。子进程传输原尺寸BGR帧，新增进程和帧传递开销需要在RDK实际负载下观察。

这能恢复用户态异常和可终止的读帧阻塞；USB/UVC硬件或内核设备失效不保证能靠进程重开恢复。持续无法恢复时会保留告警并拒发旧成功结果，不会自行重载系统驱动或重启RDK。

## 验证

在`vision_scripts`目录运行：

```bash
python3 -B -m unittest discover -s tests -p 'test_*.py'
```

`tests/test_runtime_recovery.py`覆盖所有非法长度/未知命令前缀、合法模式/六色和全部拆包点、校验错误、同批回调失败续收、过期/未来/跨模式结果、圆环发送失败重试、两种霍夫格式、真实spawn采集退出/阻塞/重开失败/打开超时及有界关闭。相机测试用640×480合成帧和假设备，不访问真实摄像头；故障期间串口命令仍能完成模式切换。

原有物料运动测试补充真实帧间隔，避免桌面测试瞬间投递导致低于20ms测速下限；没有放宽产品的停稳阈值。圆环发送线程测试按下一帧时间更新、原子发布快照，并等待实际恢复帧而非过期后的最后一帧。
